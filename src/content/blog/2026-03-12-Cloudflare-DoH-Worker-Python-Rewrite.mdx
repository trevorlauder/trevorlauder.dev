I just finished a rewrite of my Cloudflare DoH Worker, this time in Python.

The project proxies DNS-over-HTTPS queries to multiple upstream providers in parallel and returns the most restrictive result. In other words, if any provider flags a domain as malicious, it gets blocked.

This originally started as a workaround when our school division blocked DoH on my kids' devices. At first it was just a simple Cloudflare Worker proxying requests to NextDNS on a custom domain that the school didn't block. That eventually turned into this project, which I originally wrote in JavaScript because Python support in Cloudflare Workers wasn't good enough at the time. Now that it is, I've rewritten the worker in Python (my preferred language) and added some improvements.

Some of the improvements include:

- Retry logic for upstream connection issues
- Configurable ECS truncation for privacy
- DNS rebind protection
- Support for DNS JSON clients
- Optional Loki logging with a Grafana dashboard
- Domain blocklist and allowlist overrides
- Community block lists via bloom filters stored in Cloudflare KV

Allowed domains can skip fan-out entirely and go straight to a configurable non-filtering provider, while blocked domains are enforced regardless of upstream responses.

The community block list support lets you point the worker at large curated lists (like Steven Black's hosts list) that are too big to put in config. A build script fetches the sources, deduplicates them, and generates a bloom filter that gets stored in Cloudflare KV. At runtime, the worker loads the filter once on cold start and checks it in memory on every request. The default false-positive rate target is one-in-ten-billion, and with ~4.2 million domains the filter is around 25MB. A GitHub Action can keep the lists updated automatically by opening a PR when sources change.

Code and deployment instructions are on [GitHub](https://github.com/trevorlauder/cloudflare-doh-worker).
